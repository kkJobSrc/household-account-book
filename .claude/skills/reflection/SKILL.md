## 使用タイミング

作業完了後に再試行・失敗が1件以上あった場合に実行する。失敗がなければスキップしてよい。

---

## Step 1: 過去事例の検索

再試行が発生したとき（失敗直後）に実行し、類似の過去事例があれば先に活用する。

```bash
find .claude/reference/ -name "*.md" 2>/dev/null | xargs grep -l "<失敗に関するキーワード>" 2>/dev/null
```

過去事例が見つかった場合は内容を読み込み、記載された回避策を優先的に試みる。

---

## Step 2: reference ファイルの作成

作業完了後、再試行が1回以上あった場合に以下の形式でファイルを作成する。

**ファイルパス**: `.claude/reference/YYYY_MM_DD_<kebab-case-title>.md`

**記録フォーマット**:

```markdown
# <作業タイトル>

**日付**: YYYY-MM-DD
**作業種別**: 実装 / 設計 / レビュー / 分析
**試行回数**: N回

## 発生した失敗

<エラーメッセージ・失敗の内容を具体的に記録>

## 原因

<なぜ失敗したか>

## 回避策・解決方法

<最終的に機能した方法を記録>

## 再発防止メモ

<次回同じ問題を避けるためのポイント>

## 関連ファイル

- <影響を受けたファイルパス>
```

---

## Step 3: 改善案の提案

以下の条件に該当する場合、`AskUserQuestion` でユーザーに改善案を提示する：

- 同種の失敗が `.claude/reference/` に既に記録されているにもかかわらず再発した
- エージェント定義（`.claude/agents/`）またはスキル（`.claude/skills/`）の不備が失敗の原因と判断できる

提案内容の例:
- エージェントの手順に「○○の確認ステップ」を追加する
- スキルのコマンドを最新の環境に合わせて修正する
- Phase X の順序を入れ替えて特定のエラーを防ぐ
